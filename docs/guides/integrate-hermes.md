# Integrate the Hermes reference adapter

Hermes integration is optional and explicit. Mnemoir and Hermes must be importable in the same Python runtime. Mnemoir 0.2.5 is maintained against Hermes Agent 0.19.1 and exact official revision `0a62610f10cc34d696b2239b2c69fa1ba0f1ca63`. In a new shared environment run `python -m pip install 'mnemoir-provenance[hermes]'`; for existing Hermes, run that environment's Python with `-m pip install 'mnemoir-provenance[hermes]'`. If Mnemoir is already installed in that runtime and the intent is to update it, add `--upgrade`; do not add it merely for a first installation or an exact version pin. Then run `mnemoir plugin install --hermes-home <HOME>` and `mnemoir plugin status --hermes-home <HOME> --hermes-python <HERMES_PYTHON>`. The installer copies the provider and creates only its default storage parent at mode 0700. It never edits config, selects a provider, restarts a gateway, ingests, promotes, or writes back.

Selection remains separate: `hermes memory setup mnemoir_provenance`, followed by `hermes memory status`. Memory status is authoritative; `hermes plugins list` describes general plugin enablement and may disagree without meaning selection failed. Start a new process/session through the operator's normal procedure after selection. Fresh recall is expected to be empty/degraded because `ingest_on_start=false`. Use `mnemoir plugin bootstrap-profile --hermes-home <HOME> --profile-root <CONTROLLED_ROOT> --profile-id <ID> --verify-query <TEXT>` for a bounded first source. It accepts only immediate non-symlink MEMORY.md/USER.md, emits the closed bootstrap schema, is idempotent, and never promotes or writes back. A `bootstrap_no_cited_match` keeps committed evidence; replay with a matching query.

The public provider exposes exactly 12 tools: `cmc_context`, `cmc_search`, `cmc_sources`, `cmc_propose_memory`, `cmc_overflow_pressure`, `cmc_overflow_plan`, `cmc_ingest_profile_markdown`, `cmc_sync_turn_proposal`, `cmc_import_honcho_legacy`, `cmc_import_session_search`, `cmc_import_obsidian_vault`, and `cmc_writeback_status`. The `cmc_*` identifiers are retained legacy tool API names under the public `mnemoir_provenance` provider; Mnemoir documents them explicitly and does not silently rename or migrate them. Advanced list-valued configuration includes `controlled_profile_roots`, `controlled_turn_roots`, `controlled_honcho_import_roots`, `controlled_session_search_roots`, and `controlled_obsidian_vault_roots`. Provider configuration is owner-only mode 0600. The SQLite database and imported memory remain local plaintext unless the operator supplies filesystem or volume encryption.

Only a trusted `agent_context=primary` conversation may recall or mutate according to configured policy. Cron, flush, subagent, background/review, unknown, and contradictory contexts fail closed before writable initialization and return explicit disabled/degraded recall. Default `writeback_mode=propose_only`; live overflow trim requires explicit durable policy. Disable with `hermes memory off`, verify with `hermes memory status`, and retain/backup the SQLite DB separately. Removing the plugin does not delete data. The historical private provider `council_memory_core` and public provider `mnemoir_provenance` are separate: no automatic selection rewrite or DB migration occurs.
